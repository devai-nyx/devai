# OM-018 — Narrowed pre-R-0007 admission gate

**Status:** active

**Issued:** 2026-08-02

**Authority:** DEVAI Owner

## Why this rider exists

The pre-R-0007 convergence-control campaign has run for approximately one week across three
remediation campaigns and has not converged. Four independent reviews returned ten, eight,
six and ten findings. R-0007 has never started.

The cause is structural, not a lapse of effort. OM-017 requires every review to independently
recompute each topic and defect-class population, and holds that no prior `GREEN_PROVED` label
survives a newly demonstrated counterexample. That is the correct property for a terminal gate
and a fatal property for an iterative loop: the target moves on every run. Meanwhile each
repair enlarged the surface that then had to be proved, so the proof obligation grew at least
as fast as it was discharged.

Stated plainly: the repository built a second software product — the governance verifier — and
made proving that product complete a precondition for doing any work with the first. This
rider stops that.

## The narrowed pre-R-0007 admission gate

Pre-R-0007 readiness requires exactly the following, and nothing further:

1. **Exact-candidate reviewer binding.** Policy, profile, Owner mandates, reviewer binding and
   the command roster are read from one literal 40-hex candidate object, never from mutable
   worktree bytes.
2. **A clean detached candidate checkout with a frozen offline install.**
3. **One cold, uninterrupted execution of all sixteen literal convergence commands**, each run
   once, in declared order, with no argument rewriting and no injected arguments.
4. **Every one of the sixteen exits zero**, including whole coverage at the unchanged
   70/60/70/70 floors and including `ci:governance`.
5. **HEAD and tree unchanged across the run**, with every exit code retained.

A run that is signalled, interrupted, or that hits any diagnostic ceiling is `INCONCLUSIVE`.
It yields no rows at all, never the rows it had already produced.

## What moves into R-0007

The following are deferred to R-0007 as governed batch work and are recorded as deferral
records, never as an informal later list. None of them is a pre-entry obligation:

- authenticated freshness optimization and affected-test selection;
- the review transport and review state machine, including its twelve declared edges, retry
  budgets and terminal states;
- the remediation closure matrix as an admission gate, which is retained only as a disclosure
  and backlog register;
- the prior-finding topic census as a precondition for starting B0;
- two-pass smart convergence before B0. One cold pre-entry execution suffices; the two-pass
  requirement is retained for B8, after the round has done its work;
- decomposition of `scripts/run-round-close-controls.mjs`, which is not to be refactored now.

Where reuse or selection is uncertain, it is turned off and the full population is executed.
Declining to use an optimization is always permitted; claiming an unproved optimization is
correct is not.

## Control-surface freeze

No new generic control machinery lands before R-0007 entry. A defect discovered in proof
machinery is resolved by deleting or deferring that machinery, not by wrapping it in a further
schema, matrix, census or gate. Controls genuinely needed later are governed R-0007 work, seen
by an independent reviewer before they become load-bearing.

The implementation-path manifest gate already landed and is retained. It is frozen at its
current scope and receives no successors before entry.

## Admission contracts are causal

Every contract admitted under this gate must demonstrate a causal triplet: a known-green
baseline, one adversarial mutation, and the uniquely expected failure, with evidence that
execution reached the named check. A contract that fails on a neighbouring setup error, or
that passes because some unrelated sub-check of a shared finding code was satisfied, has not
exercised its subject and is not evidence.

## Review Run 2

Review Run 2 reviews **only** this admission gate and the B0 handoff. It does not review the
freshness optimizer, affected-test inference, the closure matrix, or the review transport and
state machine.

Retained from OM-017 without change: the ceiling of two substantive review runs, the literal
`claude-opus-5` reviewer selector with no fallback, the prohibition on rewriting history, role
purity by path, the 70/60/70/70 coverage floors, and the prohibition on package publication,
tags, releases, Pages deployment, real-stynx mutation and evidence streaks.

Review Run 3 remains forbidden. If Review Run 2 fails at this narrowed scope, the campaign
stops at Owner escalation with a candidate an order of magnitude smaller than the one that
failed Run 1.

## Entry sequencing

Readiness is separated from entry. A declaration-tolerant pre-B0 handoff precedes B0; the
declaration-bearing `entry-check` follows B0. B0 binding follows a PASS on the narrowed gate.

## Backup authorization

OM-017 permitted pushing only after a PASS. Approximately one week of governed work exists on
a single machine, unpushed, with no pull request. The Owner authorizes pushing the working
branch to `origin` as a backup branch for durability only.

This authorization covers durability alone. It is not authority to open a pull request, to
merge, to push `main`, to tag, to publish a package, to create a release, to deploy Pages, or
to treat a pushed branch as any form of evidence, ratification or release.
