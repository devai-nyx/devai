## Anti-repetition controls

Before Engineer implementation, the Architect and Inspector must produce a
machine-readable defect-to-population-to-test closure matrix for all eight classes.
Each row names the deterministic population query, expected complete population,
adversarial mutations, required runtime behavior, and exact test IDs. The Inspector
must demonstrate red behavior for every class and representative members of every
declared population. The Auditor preserves the exact red evidence.

Implementation may begin only after the red matrix is complete. The Engineer repairs
all eight classes as one phase and may not weaken tests, replace completeness checks
with nonempty allowlists, synthesize evidence from prose, or make mutable worktree data
authoritative.

Before freeze, the Auditor independently executes the full ordered 16-command
authoritative roster from the candidate tree, not a shorter acceptance surrogate.
Every command must PASS. The defect closure matrix must then report every row green,
and the full focused, repository, tier, coverage, sequencing, SHA-reference,
governance, diff, and clean-tree gates must pass. Any semantic/current-tree change
invalidates all candidate-bound evidence and requires regeneration before review.

Each independent review runs against a clean detached candidate-only clone, expands
every complete-class population itself, continues after blockers, and dispositions
every changed and unchanged topic exactly once. Run output must include terminal
counts and complete deterministic population queries. Truncated, partial, or
specimen-only output is invalid rather than PASS.
