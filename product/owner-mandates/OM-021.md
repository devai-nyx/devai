# OM-021 — Adopt GitHub Actions CI acceleration and authenticated evidence features

**Status:** active

**Issued:** 2026-08-06

**Authority:** DEVAI Owner

## Owner instruction

Before R-0007 begins, amend R-0007 and R-0008 so the completion sequence adopts every
GitHub Actions feature that is proper for DEVAI's threat model and demonstrably reduces CI
critical-path wall time or strengthens CI evidence without weakening an existing proof.
"Every proper feature" requires an explicit live feature census and an adopt, defer, or
reject disposition; it is not authority to enable every GitHub feature indiscriminately.

R-0007 owns the non-semantic acceleration foundation: pnpm content-store caching with frozen
installation still executed, reusable workflow/setup composition, safe dependency-graph and
matrix parallelism, event-appropriate concurrency cancellation, immutable action pins,
least-privilege permissions, structured test/coverage reports, workflow summaries, retained
timing telemetry, risk-classified commit validation, and artifact transport that never carries
PASS authority. R-0007 may
implement these features only after its existing B0 and entry gates pass and only through
its red-first, role-pure batches.

R-0008 owns authenticated reuse of canonical DEVAI result claims and GitHub-produced evidence.
Its plan must evaluate GitHub OIDC/Sigstore artifact attestations as the preferred remote
workflow identity, while retaining an explicitly bound local/offline signature mechanism
when needed. A GitHub cache key, cache hit, artifact identifier, workflow conclusion, job
name, actor name, or unverified attestation never satisfies a DEVAI gate.

## Required lane model

The amended plans must distinguish:

1. a fast feedback lane that may use dependency caches, safe parallelism, and, only after
   R-0008 authorization and proof, authenticated equivalent-claim reuse; and
2. a mandatory cold authoritative lane that starts without DEVAI result reuse and proves
   the complete applicable population, literal independent executability, build/order and
   instrumentation properties, unchanged coverage floors, and cache-independent fallback.

Dependency download caching may be used in the cold lane only when `pnpm install
--frozen-lockfile` still validates the exact lockfile and the cached bytes have no verdict
standing. The plans must bind which events require each lane, how branch protection or merge
queue checks consume them, and how a round-close exact candidate obtains an uninterrupted
non-cancelled cold run. Any GitHub settings mutation remains a separately authorized external
administrative action unless already covered by a live mandate.

## Measurement and activation

Each optimization is deny-by-default until paired evidence on one exact candidate proves
semantic population equality before timing. Record queue time, setup/install time, job and
gate duration, workflow critical path, runner class, cache hit/miss state, artifact and
attestation verification time, executed/reused populations, and correctly named file/suite/
case counts. Report absolute and percentage median critical-path change from repeated cold and
warm runs. A feature with no positive critical-path saving and no independently demonstrated
security or operability benefit remains disabled.

## Risk-classified commit validation

R-0007 must replace the unconditional full-Vitest floor for every commit with a mechanical,
fail-closed validation classifier. The classifier derives the required gate closure from the
exact diff, renames, deletions, generated-source relationships, command closure, affected-test
graph, policy/schema dependencies, and mixed-path effects. An author-provided label is never
authoritative. Unknown, ambiguous, dynamically unresolved, or classifier-owning changes widen
to the next safe complete population.

The minimum classes are:

1. `governance-text`: Owner mandates, round plans/prompts, and non-executable documentation;
   run formatting/diff, schema/frontmatter, exact reference, authority census, uniqueness,
   trace or derived-digest checks actually affected by the change, without unconditional full
   Vitest;
2. `law-and-schema`: law, policy, schema, registry, and their materializations; run prepare,
   schema/policy/trace/materialization/governance checks and mechanically affected tests,
   widening to full Vitest when closure is incomplete;
3. `runtime-and-tests`: packages, scripts, workspace tooling, workflows, test configuration,
   or tests; run prepare, static checks, the complete affected-test closure and affected
   tier/coverage gates, widening to full Vitest when impact is broad or unresolved; and
4. `candidate-and-close`: frozen candidate, convergence, round close, release eligibility, or
   classifier/trust-root activation; run the complete authoritative cold population required
   by the active close profile.

Every class still runs `git diff --check`. A mixed commit receives the strictest applicable
class. The machine-readable decision records changed paths, derived dependencies, selected
and omitted gates with reasons, policy/graph identity, and command exits. CI must include a
scheduled or main-bound cold sentinel that detects classifier false negatives. Any such false
negative disables classified validation and restores the complete prior floor until repaired.

Cost, storage, retention, repository visibility, GitHub plan eligibility, fork/PR cache trust,
OIDC subject binding, reusable-workflow identity, and action-SHA provenance must be verified
from live GitHub and immutable sources before activation. No invented benchmark, GitHub-plan
capability, check name, ruleset state, digest, or attestation subject gains standing.

## Unchanged boundaries

This rider does not authorize removal, weakening, reordering, coalescing, or population
reduction of an authoritative literal command; threshold reduction; unsound substitution
among ordinary, stage2, or coverage; trust in mutable cache bytes; publication, package
release, tag, GitHub Release, Pages deployment, evidence promotion, real-stynx mutation, or
predecessor mutation. It does not remove R-0008's requirement for a later Owner mandate that
binds its reviewer and complete local and GitHub trust policies before B0 or implementation.

Properties surrendered: **none**. If an optimization requires surrendering a proof property,
retain the slower proof and reject that optimization.
