## Tasks

1. **Stages 1–3 workflow** (`ci.yml`): static (lint + single-include-set typecheck) →
   fast gates (per-package T1/T2 + the law contract suite + `check records`-style
   guards P5 shipped) → merged coverage (T3, DB-gated job with the env flag; coverage
   thresholds from law/policy). Fail-closed defaults everywhere; no `paths:` filters
   that could silently skip gates (the predecessor's loud-failure property is a feature
   — keep it).
2. **Round-gates workflow** (manual dispatch + pre-close): T4 regression, T5 e2e/smoke
   (as far as P4's port supports — a gate that cannot run yet is a SKIPPED-RED with a
   backlog pointer in the job summary, never a green no-op), T6 containment if the
   experimental surface ported.
3. **Local-evidence skeleton**: the stage-1..3 runner as ONE documented local script
   (`scripts through porcelain where the CLI ports allowed`, else direct commands) so
   per-batch == CI by construction; the reusable evidence-gate/manifest flow itself is
   backlog (needs the evidence package fully proven) — wire the fail-closed placeholder
   that REFUSES evidence_mode rather than pretending.
4. **Scripts through porcelain** (W05.d): root scripts call `devai …` verbs where the
   ported CLI provides them (sense lint/test/type check at minimum if P4 landed them);
   direct tool invocation only where no verb exists, each such case listed in your report.
5. No release/publish workflow yet — release is post-ratification (backlog); do add the
   changeset check job (pending changesets must be classifiable, per the .changeset
   doctrine in Part VII §8.1).

## Acceptance
`act`-style local lint of workflows or yaml-parse check green · the local stage-1..3
script passes end to end on the current tree · every SKIPPED-RED enumerated ·
role-pure commits.

through devai verbs and why) / COMMITS`.
